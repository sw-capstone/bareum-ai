# AI 저장소 하네스 구조 설계 v1.4

문서 상태: 최신 AI 하네스 구조 문서
버전: `v1.4`
기준일: 2026-09-22
관리 주체: AI 담당자·하네스 담당자

## 1. 역할

AI 하네스는 `bareum-ai`의 변경이 현재 합의된 저장소 구조와 기본 품질 기준을 지키는지 반복해서 검사한다. 제품 코드를 대신 작성하지 않으며 AI 결과의 사실성이나 성능을 자동으로 보증하지 않는다.

## 2. 구성

| 경로 | 역할 |
| --- | --- |
| `harness/policy.json` | 필수 경로와 활성 검사 관리 |
| `harness/src/project_harness/` | 검사기와 CLI |
| `harness/tests/` | 검사기 자체 테스트 |
| `scripts/` | 로컬·CI 공통 실행 명령 |
| `.github/workflows/harness.yml` | Push·PR 검사와 결과 업로드 |

## 3. 현재 검사 범위

| 검사 | ID | 상태 |
| --- | --- | --- |
| 정책 유효성 | `HAR-POLICY-001` | 항상 실행 |
| 필수 경로 | `HAR-STRUCT-001` | 실행 중 |
| JSON 문법 | `HAR-JSON-001` | 실행 중 |
| Markdown 링크 | `HAR-DOC-001`~`002` | 실행 중 |
| 비밀정보 의심 패턴 | `HAR-SEC-001` | 실행 중 |

Schema·ID·서버 제품 요약 검사는 AI 저장소의 현재 검사 범위에 포함하지 않는다. AI 전용 계약·평가 자산이 확정되면 해당 자산의 소유 위치와 판정 기준에 맞춰 새 검사를 추가한다.

정책 파일의 필수 항목 `version`, `required_paths`, `checks`와 각 자료형·검사 이름·경로를 사전 검증한다. 알 수 없는 항목, 중복 JSON 키, UTF-8로 표현할 수 없는 문자열, 빈 버전·경로, 저장소 밖 경로는 `HAR-POLICY-001`로 실패하며 비활성 검사 설정도 검증한다. 생략한 검사 이름은 활성화되므로 끄려면 `false`를 명시한다. 자세한 조건은 [정책 검증 안내](../../harness/README.md#정책-검증)를 따른다.

## 4. 실행과 결과

```bash
./scripts/run-harness.sh check
./scripts/test-harness.sh
```

CI는 같은 명령을 실행한다. 결과는 `harness/reports/report.json`에 생성되고 `harness-report` 아티팩트로 제공된다.

| 상태 | 의미 |
| --- | --- |
| `passed` | 실행한 검사를 통과함 |
| `failed` | 검사 조건을 위반함 |
| `disabled` | 정책에서 검사를 비활성화함 |

현재 네 검사는 모두 실제 대상을 검사한다. 대상이 있을 때만 실행할 검사가 추가되면 `not_applicable` 상태와 처리 방법을 함께 정의한다.

## 5. 변경 책임

AI 담당자는 기능과 테스트, 평가 기준과 영역별 검사를 작성한다. 하네스 담당자는 검사 ID·판정 조건·실패 메시지·자체 테스트·CI 연결을 리뷰한다. 검사 코드나 정책을 변경한 PR에는 하네스 담당자를 필수 리뷰어로 지정한다.

## 6. 확장 원칙

새 검사는 실제 구현이나 자산과 함께 추가한다. 서버 검사가 AI 검증을 대신하지 않으며, 레포 간 검사는 합의된 계약과 실행 환경이 준비된 뒤 별도 워크플로우로 연결한다.
