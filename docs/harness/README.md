# 하네스 문서

하네스의 최신 구조와 책임 경계는 [`harness-v1.3.md`](./harness-v1.3.md)에 정의한다.
구현 진행에 따라 추가할 검사 파일의 작업별 기준은 [`harness-file-roadmap.md`](./harness-file-roadmap.md)를 따른다.

저장소는 다음 순서로 운영한다.

1. 기획·회의 자료와 관련 결정 기록을 확인한다.
2. 계약·규칙·평가 자산이 확정되면 해당 경로에서 관리하고 관련 검사를 연결한다.
3. 웹은 서버 공개 API만 소비한다. 백엔드·AI 실행 경로와 배포 단위는 관련 아키텍처가 확정된 뒤 생성하고 문서와 검사 정책에 반영한다.
4. 프롬프트는 확정된 뒤 버전 자산으로 관리한다. 제품 규칙·기준 데이터·평가 자산은 범위와 형식이 확정된 뒤 위치를 결정한다.
5. `./scripts/run-harness.sh check`와 `./scripts/test-harness.sh`를 실행한다.
6. 이슈와 PR은 노션의 확정 협업 템플릿을 기준으로 작성한다. PR의 하네스 추적 정보는 기존 항목의 작성 안내에 필요한 만큼 기록한다.
7. 현재 `CODEOWNERS`는 사용하지 않고 PR에서 필요한 리뷰어를 지정한다.

하네스 검사는 저장소 구조와 문서·계약 무결성을 정책에 정의된 범위에서 확인한다. 제품 품질과 모델 성능은 별도 평가셋과 사람 검토로 판단한다.
