# 서비스 명세 구현 요약

문서 역할: 서버 구현 요약
기획 기준: Notion에서 관리하는 기획 원문
관리 경로: `docs/product/service-spec.md`
원문 동기화 기준일: 2026-09-10
하네스 기준: [`docs/harness/harness-v1.3.md`](../harness/harness-v1.3.md)

이 파일은 계약·테스트·하네스 연결을 위한 서버용 요약본이며 기획 원문 전체를 대체하지 않는다. 문서의 미결 항목은 구현에서 임의로 확정하지 않는다.

## 1차 범위

- 계획보고서와 결과보고서를 각각 단독 문서로 검증
- HWPX·DOCX·텍스트 PDF와 직접 입력
- 스캔 이미지 문서는 1차 지원 범위에서 제외
- 업로드 파일은 20MB 제한을 기준으로 검토
- 문단·문장·표 구조화와 원본 위치 ID
- 구조·규정·표현·문서 내부 정합성 검사
- 근거와 수정안, 위험도, 점수와 검증 커버리지
- 5단계 진행 상태, 부분 실패·판단보류·처리시간·trace
- 분석 리포트와 수정 반영 문장 목록

## 확정된 경계

- 계획서와 결과서를 서로 비교하지 않는다.
- 1차에서는 승인된 기준 데이터 안에서 검색한다. 분석 중 법령 원문 API로 동적 확장하는 기능은 후속 검토 대상으로 둔다.
- 기준 데이터의 출처·기준일·검색 결과를 trace에 남긴다. 후속 단계에서 외부 원문 조회를 도입하면 외부 원문도 같은 기준을 적용하며, 근거가 확인되지 않으면 판단보류한다.
- 규칙으로 가능한 검사는 결정론 코드로 처리한다.
- 근거가 없거나 검증에 실패한 판정은 노출하지 않거나 판단보류한다.
- 미수행 검사는 사용자에게 표시하고 커버리지에서 제외한다.

## 상세 조건

- 입력·파싱·구조 분석·검증·결과 제공의 진행 상태를 단계별로 기록한다.
- 법령 검색 결과가 존재하는 것과 현재 문서의 판정을 뒷받침하는 것은 별도 검증이다.
- 서비스 기능 요구사항 `F-01~F-12`, 비기능 요구사항 `N-01~N-09`는 구현 계약과 평가 기준에서 참조한다.
- 개인 보고서와 원문·trace의 보존·삭제·소유권은 인증 세부 정책 확정 후 계약에 반영한다.

### 주요 비기능 목표

| ID | 목표 |
| --- | --- |
| `N-01` | 1차는 A4 10쪽 기준 처리시간 90초 이내를 목표로 측정. 동적 근거 확장을 도입할 경우 120초 이내를 별도 목표로 측정 |
| `N-02` | 근거 없는 위반 판정 0건 |
| `N-04` | 동일 문서 반복 실행 점수 편차 ±3 이내를 목표로 측정 |
| `N-06` | 결과에 서비스 한계와 면책 안내 표시 |
| `N-07` | 부분 실패를 표시하고 재시도 가능하게 함 |
| `N-09` | 로그에 평문 식별자를 남기지 않고 개인 보고서는 소유자만 조회 |

Recall, 오탐률, 인용 적절성, Recall@5, 수정안 채택률은 정답셋과 산식이 승인된 뒤 평가 게이트로 연결한다.

## 결정 대기

입력 형식 우선순위, 대상 지자체, 점수 산식, 표 파싱 실패 표시 단위, 정답셋 범위, 큐·워커 구성, Vector Store, 인증 세부 정책과 프론트엔드 구현 스택은 개발 과정에서 검증 결과를 보며 결정한다. 수정안은 현재 기획 기준대로 지적마다 2개를 제공한다. 백엔드·AI 기술 스택은 별도 첨부 문서의 확정 방향을 따르되 후보 모델·라이브러리 호환성은 PoC로 확인한다. 6명 역할은 별도 합의가 끝날 때까지 구현에서 고정하지 않는다.
