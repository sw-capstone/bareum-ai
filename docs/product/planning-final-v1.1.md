## 이 문서

서비스가 왜 필요하고 누구에게 무엇을 해 주며 어떤 방식으로 만드는지를 기술 용어 없이 읽을 수 있는 기획안이다.

기능별 입력·처리·예외는 서비스 명세, 만드는 원칙은 개발 원칙, 실험은 실험 계획, 제외 항목은 확장 로드맵, 결정 이유는 결정 기록, AI 호출 주변의 구현 기준은 `harness-v1.3`에서 관리한다.

## 0. 한 줄

공공기관 실무자가 계획보고서나 결과보고서 초안을 올리면, 문제가 있는 문장에 밑줄을 긋고 관련 법령 조문과 고쳐 쓴 문장을 함께 보여주는 웹 서비스.

## 1. 어떤 문제를 푸는가

주무관이 「청년 창업지원 사업 추진계획」을 올렸다가 “근거 조례가 무엇이냐”, “예산 산출근거가 없다”는 지적으로 세 번 반려당한다. 매번 지적이 다르고 매번 법령을 직접 찾아야 한다. 이 서비스는 결재를 올리기 전에 그 지적을 미리 보여준다.

| 문제 | 지금은 | 서비스가 하는 것 |
| --- | --- | --- |
| 근거를 찾는 데 시간이 든다 | 조례·지침을 매번 직접 검색 | 문장마다 관련 조문을 찾아 원문 링크와 함께 보여줌 |
| 검토자마다 기준이 다르다 | 지적 기준이 사람마다 다름 | 정해진 규칙에 따라 일관되게 판정 |
| 같은 지적으로 여러 번 반려된다 | 3~4회 재작업 | 결재 전에 스스로 검증 |

## 2. 누가 쓰는가

보고서를 쓰는 실무 담당자 한 사람이다. 결재를 올리기 전에 위험한 지점을 확인하는 용도다.

검토자나 데이터 관리자용 화면은 1차에 없고, 사용자 구분(일반/관리자)도 없다(`DEC-018`, `DEC-027`). 회원가입·로그인은 있지만 지난 분석을 저장하거나 남과 공유하는 기능은 없다.

## 3. 무엇을 해 주는가

### 동작 예시

| 단계 | 내용 |
| --- | --- |
| 입력 문장 | “「청년기본법」에 따라 관내 청년에게 창업자금을 지원한다.” |
| 판정 | 높음 · 근거 조문 미특정 |
| 이유 | 법률 이름만 있고 몇 조인지 없으며, 지자체 지원사업은 조례에 근거를 두어야 함 |
| 근거 조문 | 「청년기본법」 제17조 · 「OO시 청년기본조례」 제12조 — 국가법령정보센터 원문 링크 |
| 수정안 | “「청년기본법」제17조 및 「OO시 청년기본조례」제12조에 근거하여 관내 청년 창업자에게 창업자금을 지원한다.” |
| 점수 | 62점(예시값) → 수정을 적용하면 다시 계산 |

이 예시의 “근거 조문 미특정” 판정과 조례 조문은 규칙 등재(`DEC-037`), 대상 지자체(`DEC-002`), 조례 데이터(`DEC-022`)가 정해진 뒤에 나온다.

### 네 가지 검사

| 검사 | 무엇을 보는가 | 누가 판단하는가 |
| --- | --- | --- |
| ① 규정 | 인용한 법령·조례가 실제로 있는지, 내용이 맞는지, 있어야 할 근거가 빠졌는지. 근거가 법령인지 조례인지 상위계획인지 표시 | 규칙이 조문을 찾고 AI가 판단. AI 답은 검증을 거쳐야 보임 |
| ② 구조 | 개요·추진배경·추진내용·추진계획/결과·행정사항/향후계획과 추진근거·일정·예산·집행내역·성과 등이 다 있고 순서가 맞는지 | 규칙만 사용. 표준 목차와 대조 |
| ③ 표현 | 애매한 표현, 개조식이 아닌 문장, 결론이 뒤에 오는 문단, 기대효과에 숫자가 없는 것 | 규칙 사전 + AI |
| ④ 정합성 | 예산 총액과 항목 합계, 산출근거, 회계연도, 결과보고서의 편성액·집행액·잔액 사유·달성률 분모 | 규칙과 산술. 문서 안에서만 대조하고 다른 문서와 비교하지 않음 |

상위계획·정책과 맞는지는 1차에서 판정하지 않는다. 대신 근거의 종류만 표시한다(`DEC-023`).

## 4. 어떻게 동작하는가

| 순서 | 하는 일 | 규칙인가 AI인가 |
| --- | --- | --- |
| 1 | 문서를 올리고 계획/결과 유형을 고른다. 문단·문장·표를 나누고 개인정보 패턴이 있으면 경고 | 규칙 |
| 2 | 제목을 읽어 문단에 개요·추진근거·예산 등의 항목 라벨을 붙인다 | 규칙 |
| 3 | 네 가지 검사를 동시에 돌린다. 구조·정합성은 규칙으로 끝내고 규정·표현은 AI를 부른다 | 규칙 + AI |
| 4 | AI 답의 형식·조문 실재·근거를 검증한다. 통과하지 못하면 비노출 또는 판단보류로 남긴다 | 규칙 |
| 5 | 지적마다 수정안 2개를 만들고 시제·재발·길이를 다시 검사한다 | AI + 규칙 |
| 6 | 100점 점수와 검사한 비율을 계산해 화면과 PDF 리포트로 보여준다 | 규칙 |

### 개발 원칙

- 규칙으로 되는 것은 규칙으로 처리한다. AI는 조문 위반 여부 같은 판단과 수정안 작성만 한다.
- AI 답은 검증을 통과해야 보인다. 없는 조문은 버리고, 확신이 없으면 판단보류를 선택한다.
- 같은 문서면 같은 결과가 나오도록 AI 설정과 법령 데이터 기준일을 고정하고 결과에 버전을 기록한다.

## 6. 화면과 사용 흐름

| 화면 | 무엇이 있나 |
| --- | --- |
| S-00 로그인 | 이메일·비밀번호, 회원가입 전환 |
| S-01 홈 | 파일 업로드/직접 입력, 문서 유형 선택, 분석 시작, 샘플 문서 체험. 항상 네 가지 검사를 수행(`DEC-028`) |
| S-02 분석 중 | 예상 시간, 파싱·구조·규정·표현·정합성·수정안·점수 단계 표시 |
| S-02C 부분 실패 | 한 검사가 실패해도 나머지 결과 표시와 다시 분석 |
| S-03 결과 | 점수·등급별 건수·검사 비율, 목차, 원문 밑줄, 지적 목록 |
| S-04 지적 상세 | 원문 → 이유 → 근거 조문 → 수정안 2개 → 적용/직접 수정/무시 |
| S-05 리포트 | 점수·감점표·지적 요약·PDF 다운로드 |

### 주 시나리오

로그인 → 파일 업로드 → 계획보고서 선택 → 예상 시간 표시 → 결과 화면 확인 → 지적 문장 선택 → 근거 조문과 수정안 확인 → 수정안 적용 → 점수 재계산 → PDF 다운로드.

목표는 높은 등급 지적 0건이다. 결과보고서는 편성액·집행액·잔액 사유·달성률 분모·과거형 시제를 추가로 본다. 문단 하나만 붙여 넣어 30초 안에 확인하는 방법도 있으나 구조 검사는 제외한다.

## 7. 1차에 넣는 것과 뺀 것

### 넣는 것

로그인, 세 형식 업로드와 직접 입력, 유형 선택, 네 가지 검사, 위험도 4단계와 원문 밑줄, 수정안 2개와 적용, 100점 점수와 검사 비율, 진행 화면과 부분 실패 화면, PDF 리포트, 개인정보 경고, 처리시간 표시, 내부 성능 측정.

### 뺀 것과 다시 볼 조건

분석 중 법령을 새로 가져오기(복잡도), 계획서와 결과서 비교(범위), 검사 범위 선택(점수 산출 불가), 상위계획 부합성 판정(오탐), AI가 AI 답을 재검토(시간·비용), 지난 분석 저장·공유(범위), 관리자 화면(과잉), 수정본 HWPX·DOCX 내보내기(난이도·팀 결정 대기), 등급·레이더 차트(산출식 미확정), 선례(CBR) 기능(실험으로만). 자세한 이유와 재검토 조건은 확장 로드맵에서 관리한다.

## 8. 얼마나 잘해야 하는가

| 목표 | 기준 |
| --- | --- |
| 처리 시간 | A4 10쪽을 90초 안에 |
| 규정 지적 재현율 | 정답 문장 모음에서 재현율 0.70 이상, 오탐율 0.30 이하 |
| 근거 없는 위반 판정 | 0건. 법령 데이터에 없는 조문 인용도 0건 |
| 수정안 채택 | 실무자 5인이 문서 3건씩 작성하고 지적의 절반 이상에서 수정안 채택 |
| 동일 문서 재현성 | 재분석 점수 차이 ±3점 이내, 규칙 검사 결과는 완전히 동일 |

“100%” 같은 주장은 하지 않는다. 판단보류 비율은 목표치 없이 항상 보고한다.

## 9. 실험 세 개

| 실험 | 질문 | 발표에서 보일 것 |
| --- | --- | --- |
| E-3 검증 장치의 효과 | 판단보류와 조문 실재 검사를 붙이면 억지 판정과 가짜 조문 인용이 줄어드는가 | 적용 전(H0)·후(H1) 수치표와 그래프 |
| E-1 구조 라벨링 | 규칙만으로 문단에 항목 라벨을 붙이는 비율과 AI 보조 효과는 어떤가 | 유형별 확정 비율과 오류 분포 |
| E-2 선례(CBR) 활용 | 과거 수정 사례가 수정안 채택 가능성을 높이는가 | CBR ON/OFF 수정안에 대한 평가자 3인의 선택 결과 |

실험 결과가 좋아도 1차 범위는 바뀌지 않는다. 2차 반영은 확장 로드맵의 조건에 따른다.
