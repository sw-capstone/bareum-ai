# DEC-RULE-001 규칙 카탈로그 공식 원천

- 상태: `검토 필요`
- 결정일: 2026-09-09
- 소유 역할: `ai-team`
- 관련 문서: `docs/harness/harness-v1.3.md`

## 쟁점

데이터셋 제안 문서의 오래된 `rules.yaml`과 최신 `오류/위반 유형 카탈로그`의 규칙 필드와 ID 체계가 서로 다르다. 현재 저장소에는 확정된 로컬 규칙 카탈로그가 없다.

## 검토 제안

최신 `오류/위반 유형 카탈로그`와 그 첨부 `rules.yaml`을 제품 규칙의 공식 원천으로 사용한다. 이전 데이터셋 문서의 규칙 정의는 최신 카탈로그와 일치하는 부분만 참고한다.

제품 규칙 ID는 카탈로그의 `LAW-01`, `FMT-01`, `STR-01`, `CON-01`, `EXP-01` 형식을 그대로 사용한다. 프로젝트 자산 추적용 `RULE-<DOMAIN>-<NNN>` ID와 혼합하지 않는다.

## 승인 시 적용 원칙

1. 최신 첨부 파일을 검증·import하기 전까지 로컬 규칙 목록을 만들지 않으며, 실행 가능한 규칙으로 표시하지 않는다.
2. 카탈로그에 없는 번호를 추측하여 채우지 않는다.
3. `CON-05~07`, `FMT-07`, `STR-02`는 별도 확인 전까지 미확정으로 기록한다.
4. 규칙 변경은 카탈로그 버전, 변경 이유, 영향 평가, 회귀 결과를 함께 남긴다.
5. 로컬 규칙 스키마와 데이터셋 라벨은 카탈로그의 필드·ID를 소비하고, 사용자 출력용 심각도는 별도 매핑으로 관리한다.

## 영향

- 담당자가 규칙 자산을 추가할 때 카탈로그 필드와 출력 심각도의 구분을 별도 Schema로 확정한다.
- 데이터셋·프롬프트·평가 리포트는 카탈로그 버전을 기록해야 한다.
- 이전 규칙 파일을 자동으로 active 처리하면 안 된다.

## 재검토 조건

- 팀이 Git 저장소를 새 규칙 SSOT로 승인하는 경우
- 카탈로그의 규칙 ID·필드가 변경되는 경우
- 첨부 `rules.yaml`의 전체 검증 결과가 현재 계약과 호환되지 않는 경우
