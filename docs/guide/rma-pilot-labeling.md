# RMA 파일럿 라벨링 안내

RMA 파일럿에 참여하는 라벨러를 위한 안내다. 판정 기준은 [RMA Move–Step 카탈로그](../specs/rma-move-step-catalog.md), 파이프라인 전체는 [RMA 라벨링 파이프라인 설계](../specs/rma-labeling-pipeline.md)를 따른다.

## 1. 왜 하는가

- 모델(GPT-6 Sol) 라벨이 맞는지 잴 **사람 정답**을 만든다. 정답이 있어야 모델 라벨을 검사 규칙(EXP·CON)에 써도 되는지 판단할 수 있다.
- 두 사람이 같은 기준으로 같은 판정을 내리는지 확인한다. 자주 갈리는 경계는 카탈로그를 고칠 곳이다.

## 2. 규모와 진행

| 항목 | 내용 |
| --- | --- |
| 대상 | Dev 보고서 6편(계획 3, 결과 3)의 일부 구간, 판정 단위 약 150개 |
| 예상 시간 | 1인당 약 2.5시간. 나눠서 해도 된다 |
| 진행 | ① 각자 독립 라벨링 → ② 두 사람 결과를 나란히 보며 조정 → ③ 조정본을 정답으로 확정 |

**독립 라벨링 원칙**
- 조정 전까지 서로의 라벨을 보지 않고, 판정을 상의하지 않는다.
- 모델 라벨을 보지 않는다. 모델 판정을 먼저 보면 사람 판정이 끌려간다.
- 기준이 애매하면 판정을 미루지 말고 `UNDETERMINED`와 사유를 남긴 뒤 메모해 둔다. 조정 때 함께 정한다.

## 3. 준비

1. develop 최신 코드를 받는다(RMA PR이 merge된 뒤).

   ```bash
   git switch develop
   git pull
   uv sync
   ```

2. 파일럿 폴더(`rma_pilot_*`)를 전달받아 원하는 곳에 압축을 푼다. 폴더 안에 `pilot.json`, `requests/`, `snapshots/`가 있다. 파싱 결과가 폴더 안에 들어 있어 원본 PDF나 API 키는 필요 없다.

## 4. 화면 열기

레포 루트에서 실행한다. `<이름>`은 영문으로 적는다(예: `seamooll`).

```bash
uv run python -m bareum_ai.dataset.rma.review serve --work <파일럿 폴더> --annotator <이름>
```

- 브라우저가 자동으로 열린다. 터미널에 찍힌 주소(`http://127.0.0.1:8765/` 등)로 직접 들어가도 된다.
- 내 PC에서만 열리며 다른 사람은 접속할 수 없다.
- 끝낼 때는 터미널에서 `Ctrl+C`를 누른다. 다시 열면 저장된 라벨이 그대로 나온다.

## 5. 화면 구성

- **위쪽 탭**: 문서 6편. `남음 N`은 아직 검증을 통과하지 못한 단위 수, `완료`는 문서 전체 통과다.
- **왼쪽**: 문서 원문. 진한 블록만 판정 대상이고 흐린 블록은 문맥이다. 왼쪽 띠가 빨간 블록은 아직 오류가 있고, 초록은 통과다.
- **오른쪽**: 고른 블록(또는 표 행)의 편집 영역과 검증 결과.

바뀔 때마다 자동 저장되고, 저장할 때마다 검증 결과가 갱신된다. 별도 저장 버튼은 없다.

## 6. 작업 순서

### 6.1 문서 단위 판정 (문서마다 먼저)

오른쪽 위 **문서 단위 판정**을 누른다.

| 항목 | 기록 | 근거 |
| --- | --- | --- |
| 작성 목적 | 기획·상황·결과·검토·기타 중 주된 목적 하나. 모르면 `판정 불가`와 사유 | 왼쪽 원문에서 근거 구절을 드래그한 뒤 **선택 구절로** |
| 업무 주제 | 행사·교육 중 문서의 **주된 업무**에 해당하는 것. 하위 활동으로 일부 들어간 것은 넣지 않는다. 둘 다 아니면 체크하지 않는다 | 주제마다 근거 구절 |
| 표준 목차 | 적용 근거가 있는 목차. 목적·주제만 보고 고르지 않는다. 없으면 `없음·선택 불가` | `목차 근거`에 이유를 적는다 |

### 6.2 블록 판정

1. 왼쪽에서 판정할 블록의 **근거 구절을 드래그**한다. 블록이 자동으로 선택되고, 오른쪽 위에 `선택한 근거`가 표시된다.
2. **선택 구절로 기능 추가**를 누르고 Move를 고른다.
3. 고른 Move에 Step이 있으면(GROUNDS·PROBLEM·ASSESSMENT·EFFECT) 해당 Step의 근거를 드래그한 뒤 Step을 체크한다. **Step 상태**를 고른다.
   - 판정 완료: Step을 확인했다
   - 일부 판정: 일부만 확인했다. 사유를 적는다
   - 판정 불가: Move는 맞지만 Step을 정할 수 없다. 사유를 적는다
4. 한 블록에 기능이 더 있으면 2~3을 반복한다(예: 근거 제시 + 실행 계획, 명세 + 붙임 참조).
5. 주 기능이 분명하면 그 기능 왼쪽의 동그라미를 고른다. 대등하면 **주 기능 없음(대등)**을 고른다.

**특수한 경우**
- **구간 이름만 있는 제목**('추진배경', '내용' 등): 기능을 추가하지 않고 비워 둔다. 비워 둘 수 없는 블록이면 검증 오류(V12)가 난다.
- **SPEC**: **선택 구절을 값으로 추가**로 값 구절을 넣고, 항목(사업명·사업기간·사업비 등)을 고르고 원문 항목명을 적는다. 허용 항목에 없으면 `대응 불가`와 사유를 적는다.
- **UNDETERMINED**: 사유를 고른다. 파싱이 깨진 입력(표가 문단으로 흩어진 조각, 두 블록으로 쪼개진 문장)은 `INPUT_BROKEN`, 앞뒤 문맥이 없어 판단할 수 없으면 `CONTEXT_MISSING`, 문맥을 봐도 기능을 정할 수 없으면 `AMBIGUOUS`다.
- **참고 블록**: 판정에 다른 블록을 참고했으면 블록 번호를 쉼표로 적는다(예: `0012, 0013`).

### 6.3 표 판정

표는 **행 단위로 판정하고 근거는 셀로** 남긴다.

1. 오른쪽에서 **열 제목 행**과 **행 제목 열**을 체크한다.
2. 왼쪽 표의 **행 번호**를 눌러 행을 고른다.
3. **행 역할**을 고른다: 본문 행 / 열 제목 행 / 빈 행.
4. 본문 행이면 셀 안의 구절을 드래그하거나 **셀을 더블클릭**(셀 전체가 근거)한 뒤 기능을 추가한다. 같은 행, 열 제목 행, 병합 시작 셀만 근거가 될 수 있다. 회색 기울임 글씨는 병합으로 이어 받은 값이라, 고르면 시작 셀로 바뀐다.
5. 합계·총계 행은 SPEC으로 판정한다(금액이면 사업비, 시간·건수·인원이면 규모).
6. 표 구조가 깨져 행을 읽을 수 없으면 **표 상태**를 `읽을 수 없음`으로 바꾸고 사유를 적는다.

## 7. 자주 헷갈리는 판정

| 경우 | 판정 |
| --- | --- |
| 본문 안의 "(※ 세부내역 별첨)" | 블록의 다른 기능과 함께 `ANNEX_REF`도 적는다 |
| "교육 3회 실시", "26명 참석"처럼 숫자가 있는 활동 보고 | `EXECUTION`. 활동으로 생긴 산출물·변화일 때만 `OUTCOME` |
| "2019. 5∼6. : 수요기업 공모" 같은 추진일정 항목 | `SPEC`(일정)만. 활동 명칭만 나온 것은 `ACTION`이 아니다 |
| 집행액·잔액, 예산 비목 설명 | `SPEC`(사업비) |
| 현재 상태 보고 vs 문제 진단 | 부족·결함을 진단해야 `PROBLEM`, 상태만 말하면 `STATUS` |
| 앞으로 할 일 vs 이행 요청 | 실행 방법은 `ACTION`, 담당 지정·제출·협조 요청이 중심이면 `FOLLOWUP` |
| 설정한 목표 vs 예상 편익 | 달성 의지는 `PURPOSE`, 시행 후 예측은 `EFFECT` |
| 결과 보고 vs 결과 평가 | 결과를 그대로 보고하면 `OUTCOME`, 달성도·한계·시사점을 판단하면 `ASSESSMENT` |
| 결재란(주무관·팀장·과장 서명 칸)이 판정 대상으로 나온 경우 | `OTHER`. 파서가 결재란으로 확정하지 못해 본문에 남긴 표다 |

나머지 경계는 카탈로그 2.14절을 본다. '~함'이나 섹션 제목만으로 완료·예정을 정하지 않고 앞뒤 문맥을 함께 본다.

## 8. 검증 메시지

| 코드 | 뜻 | 조치 |
| --- | --- | --- |
| V02 | 아직 라벨이 없다 | 판정하거나, 구간 제목이면 그대로 둔다 |
| V05 | Move를 고르지 않았다 | Move를 고른다 |
| V06 | Step과 Step 상태가 맞지 않는다 | Step을 체크하거나 상태·사유를 고친다 |
| V07 | UNDETERMINED 사유가 없다 | 사유를 고른다 |
| V08 | SPEC 항목이 없거나 허용 항목이 아니다 | 항목을 추가하거나 `대응 불가`와 사유를 적는다 |
| V09 | 근거 구절을 원문에서 찾지 못했다 | 근거를 다시 드래그한다 |
| V10 | 표 근거 셀이 허용 범위 밖이다 | 같은 행·열 제목 행·병합 시작 셀을 고른다 |
| V11 | 표 행 역할이 비었거나 본문 행에 기능이 없다 | 행 역할을 고르고 기능을 추가한다 |
| V12 | 비워 둘 수 없는 블록이 비었다 | 기능을 추가한다(모르면 `UNDETERMINED`) |
| D01 | 문서 단위 판정이 비었거나 근거가 없다 | 6.1을 채운다 |

## 9. 끝나면

1. 모든 탭이 `완료`인지 확인한다.
2. 파일럿 폴더의 `labels/<이름>/` 폴더를 압축해 전달한다.
3. 판정하며 헷갈린 경계를 메모해 두었다가 조정 때 공유한다.
