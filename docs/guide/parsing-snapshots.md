# 파싱 결과 고정과 라벨 연결

라벨링을 시작하기 전에 파서 수정과 원문 검수를 끝내고 입력을 고정한다. 고정 결과를 변경하면 새 스냅샷을 만들고 새 라벨 작업으로 진행한다. 기존 블록 ID를 새 파싱 결과에 자동 이전하지 않는다.

## 파서 처리 정책

- 일반 문단은 공백 경계를 보존한다. 표시용 `text`의 연속 공백은 한 칸으로 정리할 수 있지만 `source_text`는 원문을 유지한다. 제목 복원에만 자간 축약을 적용한다.
- 스키마 1.2.0의 셀 줄바꿈 정책은 `preserve-boundaries-v1`이다. 일반 줄 경계는 정렬·셀 폭과 관계없이 공백으로 보존한다. 셀 처리에는 문단용 자동 어절 결합을 사용하지 않는다. 숫자 범위의 명시적 `~`/`∼`/`〜` 뒤만 연결하고, 원문에 공백이 있으면 그 공백을 유지한다. 한 글자씩 세로로 쌓은 표기는 원문 순서대로 복원하되 검수 대상으로 기록한다.
- 각 셀의 `line_breaks`에는 줄 경계의 `source_offset`(source_rows 셀 문자열), `text_offset`(rows 셀 문자열), 적용한 separator, reason, needs_review를 남긴다. 작성 공백 없이 끊긴 일반 줄은 공백으로 보존하고 `table_cell_linebreak_review` 경고를 남긴다. 예컨대 `관급`/`자재`도 좌표만으로 붙이지 않으며 검수 후에 해석을 확정한다. 원문 문자열과 셀 경계는 그대로 보관한다.
- 빈 셀이 많은 표는 경고와 함께 보존한다. 다만 배경 채움을 제외한 재탐색에서 서로 떨어진 표가 둘 이상 확인되고 그 밖에 텍스트 줄이 남는 경우에는 큰 격자를 분리한다. 복원된 표의 셀은 유지하고 표 밖 글자는 본문 처리로 돌리며 `table_background_grid_split` 경고를 남긴다. 재탐색 근거가 없으면 빈칸만으로 표를 버리지 않는다.
- 결재란 정책은 `first-page-prefix-v3`다. 첫 페이지 상단에서 본문이 시작되기 전의 서식만 후보로 삼고, 같은 가로 범위에서 제목·문장·미확인 문구를 만나면 그 뒤까지 제외하지 않는다. 문서 끝의 결재란은 자동 제외 대상이 아니다. 항목 표와 서명 표 사이 간격은 페이지 너비의 8%까지 허용하며, 윗선 차이가 2pt 이내인 경우에만 12%까지 허용한다. 사이에 본문이 있으면 연결하지 않는다.
- 항목 단어집은 보조 근거다. 짧은 항목명과 오른쪽 값 칸이 반복되는 배치로 미등록 항목도 후보로 받는다. 알려진 항목 두 종류 이상 또는 항목/값 세 행 이상에 결재·협조 영역의 근거가 함께 있어야 확정할 수 있다. 직위 두 종류를 필수로 요구하지 않으며 빈 서명 칸과 가로/세로 서명 배치를 허용한다. 일반 표와 구분할 근거가 부족하면 `approval_region_ambiguous` 경고를 남기고 본문에 유지한다.
- 제외 범위는 후보 표 각각의 테두리 안으로 제한한다. 줄 간격으로 본문까지 확장하지 않으며, 글자 배치와 블록 복구가 확인된 경우에만 `excluded_from_retrieval`을 지정한다. 일반 본문 셀이 연결되거나 격자의 빈틈에 글자가 있으면 해당 표를 유지하고 경고한다. 소비자도 이 최종 제외 여부를 따라야 하며 외접 사각형으로 본문을 다시 제외하면 안 된다.
- 같은 테두리가 중복 셀을 만들지 않도록 1pt 이내의 괘선 좌표를 정렬한다. 결재란 복구 시 표 경계는 선 위치 보정을 고려해 2pt, 문단 경계는 1pt 오차까지 허용한다. 텍스트가 없는 이미지 블록은 결재란에 흡수하지 않고 별도로 보존한다.
- 머리말은 결재란과 별도로 처리한다. 페이지 가장자리의 저장/출력 정보는 실제 코퍼스에서 확인한 `저장 : 사용자 / 부서 (YYYY-MM-DD HH:MM:SS)` 형식으로 판별한다. 같은 가장자리 위치에 여러 페이지 반복되는 문구도 머리말/꼬리말로 처리하며, 원문과 판정 이유를 남긴다. 첫 페이지의 작은 글씨만으로 제외하지 않는다. 근거가 없는 작은 상단 문구는 `header_ambiguous` 경고와 함께 본문에 남기고 결재란 확장도 막는다.
- 제목처럼 보이는 표도 `kind=table`, 전체 `text`, `rows`, `source_rows`, `cells`를 보존한다. 별도 `heading_hint`에 제목의 text/marker/level, 근거와 confirmed/needs_review 상태를 기록한다. 글자 크기만으로 확정하지 않고 표제어와 부호/크기 근거를 함께 확인한다. 확정한 해석은 섹션 계층과 Markdown에 사용하되 라벨 span은 항상 원래 `block.text` 기준이다. 불확실하면 일반 표로 출력하고 `table_heading_ambiguous` 경고를 남긴다.
- 문서 제목 후보와 이어지는 제목 줄에서 기관명을 확인할 때만 공백을 제거해 비교한다. `파 주 시`의 표시 공백과 원문은 유지하며, 기관명 자체를 제목으로 삼거나 제목에 합치지 않는다.

## 고정 도구

```bash
uv run python -m bareum_ai.dataset.parsing.snapshot report.pdf -o parsed_output/snapshots
```

내용 해시별 `snap_<sha256>/` 폴더에 `parsed.json`과 `manifest.json`을 만든다. 기존 결과를 덮어쓰지 않으며 같은 입력을 반복하면 같은 스냅샷을 사용한다. 읽을 때 저장된 manifest와 내용 해시를 다시 검증한다.

`parsed_content_sha256`은 블록 ID·텍스트·원문·좌표·표 셀·제외 여부·섹션·페이지·도식·경고와 파서 설정/구현 해시/의존성 버전을 포함한다. 실행 통계는 제외한다. `snapshot_id`, PDF SHA-256, 파서 스키마, 구현 해시, 설정, PyMuPDF 버전을 manifest에 기록한다.

라벨에는 `snapshot`과 `block_sources`를 기록한다. `block_sources`는 블록당 한 번 `page`, 회전 전 PDF 포인트 기준 `bbox`, 전체 `source_text`, `text_sha256`을 보관한다. 문자 범위는 `span_basis`에 명시된 문자열 기준이며 `source_text`의 위치로 바꾸어 해석하지 않는다.

라벨 소비자는 스냅샷/원문 참조 일치, 블록 존재, 문자 범위와 `quote` 일치를 검증한다. 스냅샷 고정 후 파서 구현을 바꾸어도 이미 고정한 입력은 그대로 사용한다. 새 파싱 결과에 기존 라벨을 재연결할 때에는 별도 원문 검수가 필요하다.

원문 검수가 필요한 경고는 스냅샷에도 보존된다. 자동 구조 검사 통과와 원문 검수 완료를 따로 기록한다.
