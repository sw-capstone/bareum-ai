# 판정 예시 (RMA Move–Step 카탈로그 2.14, 4.2, 4.3)

## 인접 Move의 경계

| 경계 | 확인할 차이 | 예 |
| --- | --- | --- |
| BACKGROUND / STATUS | 추진의 외부 계기인지, 현재 상태 보고인지 | BACKGROUND: 비대면 서비스 수요가 늘어 온라인 창구 도입이 필요하다. / STATUS: 현재 온라인 창구 이용 비율은 30%다. |
| PURPOSE / EFFECT | 설정한 달성 목표인지, 시행 후 편익 전망인지 | PURPOSE: 처리 기간을 7일로 단축하는 것을 목표로 한다. / EFFECT: 시스템 도입으로 처리 기간이 7일로 줄어들 것으로 예상된다. |
| STATUS / PROBLEM | 상태 보고를 넘어 부족·결함·개입 필요성을 진단하는지 | STATUS: 현재 담당 인력은 2명이다. / PROBLEM: 담당 인력이 2명에 불과해 접수된 민원을 기한 내 처리하기 어렵다. |
| ACTION / FOLLOWUP | 실행할 방법인지, 담당 지정·제출·협조 등 이행 요청인지 | ACTION: 9월부터 온라인 접수창구를 운영할 계획이다. / FOLLOWUP: 각 부서는 8월까지 접수창구 담당자를 지정하기 바란다. |
| EXECUTION / OUTCOME | 활동 수행 보고인지, 확보한 산출물·확인된 변화인지. 숫자 유무로 정하지 않는다 | EXECUTION: 담당자 교육을 3회 실시했다. / OUTCOME: 교육 후 업무 오류율이 10%에서 5%로 감소했다. |
| PROBLEM / ASSESSMENT | 개입할 문제 제기인지, 사업 결과의 달성도·한계 평가인지 | PROBLEM: 지역별 접근성 격차로 일부 주민이 서비스를 이용하기 어렵다. / ASSESSMENT: 이번 사업은 일부 지역에만 적용돼 접근성 격차를 해소하는 데 한계가 있었다. |
| SPEC / 다른 Move | 항목·값 제시인지, 목표·필요성·효과 주장인지. 표 형식만으로 SPEC을 붙이지 않는다 | SPEC: 대상: 민원 담당 직원 30명 / PURPOSE: 민원 담당 직원의 업무 정확도 향상을 목표로 한다. |

## 문맥에 따른 판정

| 대상 표현 | 함께 확인한 문맥 | 판정 |
| --- | --- | --- |
| 담당자 교육 실시 | 향후 일정: 다음 달 실시 예정 | ACTION |
| 담당자 교육 실시 | 실시 결과: 지난달 완료 | EXECUTION |
| 담당자 교육 실시 | 시점·완료 여부를 알 수 있는 문맥 없음 | UNDETERMINED / CONTEXT_MISSING |
| 표의 셀: 담당자 교육 3회 | 열 제목: 추진 실적 / 행 제목: 6월 | EXECUTION |

## 복합 기능과 Step

- "시스템 도입으로 처리 시간이 단축될 것으로 기대된다." → EFFECT 하나. 도입은 편익의 전제이며 별도의 실행 계획이 아니다.
- "시스템을 도입할 계획이며, 처리 시간 단축이 기대된다." → ACTION + EFFECT. 실행 계획과 예상 편익을 각각 진술한다.
- "관련 조례에 따라 시스템을 도입할 계획이다." → GROUNDS(ORDINANCE, 근거 "관련 조례에 따라") + ACTION(근거 "시스템을 도입할 계획이다"). 주 기능은 ACTION이다.
- "처리 시간이 20% 감소하고 주민 이용 편의가 향상될 것으로 예상된다." → EFFECT, steps에 QUANTITATIVE("처리 시간이 20% 감소")와 QUALITATIVE("주민 이용 편의가 향상"), step_status는 determined다.
- "관련 규정에 따라 추진한다." → GROUNDS. 규정 종류를 알 수 없으면 steps는 빈 목록, step_status는 undetermined, step_reason에 "규정 종류를 확인할 문맥 부족"을 적는다. Move까지 UNDETERMINED로 바꾸지 않는다.
